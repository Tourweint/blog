### 一、 内部列表页的全局逻辑：过滤器 (Filter)

在进入“原触发”后的内页，顶部应该有一个极其精简的导航/过滤器，让用户在不同内容间快速切换，而不是退回首页。

* **布局建议：** 顶部居中或左侧的一行“胶囊型”标签（Pills）。
* **文案：** `全部` · `原论` · `原点` · `原型`
* **辅助信息：** 在标签旁边用浅灰色显示数量（如：原论 12），增加“沉淀感”。



### 二、 三大板块的“原子化卡片”设计

这是解决“乱”的关键。**不同的内容属性，需要不同的信息结构。**

#### 1. [原论] 板块：强调“导读性”

* **痛点：** 思考类文章通常很长，读者怕点进去发现没兴趣。
* **设计方案：** * **核心块：** 标题 + 一句核心结论（One-sentence summary）。
* **必要元素：** 阅读时长（例如 `5 min read`）、关键引用（从正文中抽取出最精彩的一句话作为预览）。
* **易读性技巧：** 使用大号字体的标题，下方紧跟较淡色彩的摘要。



#### 2. [原点] 板块：强调“即时性”

* **痛点：** 碎片内容太细碎，点开看很麻烦。
* **设计方案：** * **核心块：** **直接展示全部内容**（如果字数在 200 字以内）。
* **样式：** 模拟“便签”或“推文”样式。不需要标题，直接显示文字。
* **必要元素：** 时间戳（精确到日）、来源（如：#见闻、#深夜）。



#### 3. [原型] 板块：强调“功能性”

* **痛点：** 项目类内容，读者最想看“这是干嘛的”和“能不能运行”。
* **设计方案：** * **核心块：** **[意图]** (Why) + **[效果]** (Result)。
* **必要元素：** * **Tech Stack 标签：** 如 `AI: Claude 3.5` / `Code: Python`。
* **状态图标：** `Done` (已上线) / `WIP` (开发中)。
* **链接：** GitHub 或 Demo 直达按钮。

### 三、 简介块与页面结构设计表

| 区域 | 设计建议 | 作用 |
| --- | --- | --- |
| **页面页头 (Header)** | 沿用首页的标题和副标题，但缩小比例，腾出首屏空间。 | 品牌一致性。 |
| **简介块 (Hero)** | **长短建议：中等。** 放在列表上方。解释“为什么我要把这三个东西放在一起”。 | 确立页面价值观。 |
| **内容卡片 (Card)** | **统一宽度，高度自适应。** 采用瀑布流或垂直列表。 | 保持视觉节奏。 |
| **元数据 (Meta)** | 放在卡片底部，用极细、极淡的字体。 | 降噪，不干扰阅读。 |

### 四、 如何展示“AI 参与度”？（你的特色）

既然你特别强调“不进行具体生产”，在内页的每一条内容下方，可以增加一个**协作标签**：

> **Collaboration Trace:**
> 🧠 **Inspiration:** My observation on [Source]
> 🤖 **Generation:** Built by GPT-4o / Refined by Claude
> ⚡ **Action:** [Prompt/Process Link]

### 建议的设计稿布局（从上到下）：

1. **极简导航**（回到首页 / 切换分类）
2. **板块简介**（一两句话：*“这里的原型是我播下的种子，AI 替我浇灌出的结果。”*）
3. **内容流**：
* [原论] - 宽卡片（沉稳）
* [原点] - 窄卡片或并排（轻盈）
* [原型] - 带预览图或图标的卡片（硬核）
